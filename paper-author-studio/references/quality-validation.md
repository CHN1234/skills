# 质量验证

验证的目标是确认这是一篇完整、统一、具有目标作者判断的稿件，而不是证明它使用了某些固定句式。

## 1. 研究主线

- 能否用一句话说清论文研究身份？
- Title、Abstract、Introduction、Method、Experiments 和 Conclusion 是否指向同一中心故事？
- 主贡献是否明显高于实现细节和次要分析？
- 中心故事是否通过实现、结果、反证和表述强度四项资格检查？
- 每张主表或主图是否承担一个明确论证任务？

## 2. 方法与实验

- Method 是否准确覆盖核心数据流、模块关系、目标函数和训练/推理过程？
- 是否遗漏影响结果理解的关键实现设置？
- Experiments 是否按研究问题组织？
- 主比较、跨设置模式、消融和异常结果是否得到解释？
- 消融是否真正对应所声称的组件作用？

## 3. Related Work

- 是否覆盖 baseline、最近邻路线和 baseline 之后的重要工作？
- 每篇关键引用是否确实支持对应描述？
- 是否按问题或路线综合，而不是逐篇列举？
- 本文位置是否具体到方法或能力差异？
- 是否独立检查了前向引用、替代路线、最近邻方法和目标 venue 的近期工作？

## 4. 目标作者保真度

- 论文是否采用档案中提炼出的研究问题塑造方式？
- 官方要求、语料共性、锚点策略和当前适配是否没有混为一谈？
- 贡献尺度、章节动作和实验叙事是否与目标语料相符？
- 随机抽取三个段落，是否能观察到档案中的段落判断和表达 DNA？
- 删除 venue 名称后，文本是否仍像该研究社区的成熟论文，而非通用生成稿？

## 5. 语言与一致性

- 术语、缩写、符号、数据集、baseline 和指标名称是否统一？
- 摘要数字是否能在 Results 中找到？
- 正文数字是否与表图一致？
- 图表标签和引用是否存在？
- 是否残留 TODO、TBD 或作者输入占位符？
- 是否存在模板化开场、重复总结、空泛强调和同构句式？

## 6. 验证方式

先由写作流程完成一次全文自检。若用户要求高强度验证且环境支持独立评审，再让未参与写作的评审者只读取研究材料、作者档案和成稿，分别评价：

1. 研究内容忠实度；
2. 中心故事完整度；
3. 目标作者保真度；
4. 段落与语言质量。

评审结果必须指出具体章节或段落，并给出可直接替换的修改。不要只给分数。

## 7. 交付门槛

满足以下条件即可交付：

- 完整稿件已经生成；
- 中心故事跨章节一致；
- 关键方法和结果均已写入；
- 目标作者档案已实际影响结构和表达；
- 确定性一致性检查中人工确认的错误已经处理；
- 少量缺失信息已集中标明，且不妨碍用户继续修改。

不要因为次要材料不完整而把整篇正文扣在检查点。只有中心结果缺失或两个候选故事会形成实质不同论文时，才需要先向用户确认。
