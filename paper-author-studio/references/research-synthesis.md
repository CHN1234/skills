# 研究理解与中心故事

本阶段把项目材料转化为资深作者可以使用的研究模型。目标是找到最值得写、能统一方法与实验、适合目标社区的中心故事。

## 1. 读取 baseline

从论文和代码恢复：

- 任务定义与输入输出；
- 主要假设；
- 数据与控制流；
- 核心模块与优化目标；
- 训练和推理路径；
- 作者明确提出的限制；
- 用户工作真正涉及的局部边界。

Baseline 的论文表述和代码实现不一致时，分别记录“论文方法”和“实际实现”，再判断用户实验以哪个为起点。

## 2. 确立材料版本与冲突裁决

先确定本轮写作实际采用的代码、配置、结果和稿件版本。按信息类型选择主要来源：

| 信息 | 主要核对来源 |
|---|---|
| 实际方法行为 | 最终使用的代码路径、配置和版本 |
| 训练与评价协议 | 实际入口、配置和日志 |
| 数值结果 | 原始结果、汇总脚本和最终表格 |
| 设计动机 | 用户说明或已有研究记录 |
| Venue 硬性要求 | 当前官方投稿指南 |
| 写作规律 | 匹配论文语料中的重复模式 |

代码说明做了什么，但不自动说明为什么这样设计。冲突会改变中心主张、关键数字或实验口径时暂停确认；其他冲突记录采用版本和理由后继续，不把写作变成材料审计。

## 3. 读取用户方法代码

沿实际入口追踪，而不是按文件夹浏览后猜测：

```text
入口与配置
→ 数据准备
→ 模型构建
→ 前向数据流
→ 损失与优化
→ 推理
→ 评价
```

建立差异表：

| 变化 | baseline | 用户方法 | 改变的信息或求解过程 | 可能对应的贡献 |
|---|---|---|---|---|
| 模块/路径 | 原行为 | 新行为 | 实质变化 | 候选定位 |

将重命名、工程适配和必要胶水代码与研究变化分开。多个变化若服务同一机制，优先寻找统一方法思想。

## 4. 读取实验与结果

从实验代码和配置恢复：

- 数据集、划分和预处理；
- baseline 与比较方法；
- 训练预算和关键超参数；
- 指标及其科学含义；
- 重复次数、随机种子和统计口径；
- 主实验、消融、敏感性、效率、可视化和失败案例之间的关系。

从结果中提取模式，而不是只找最大值：

- 总体优势或总体持平；
- 优势集中在哪些任务、条件或指标；
- 是否存在性能—效率、精度—稳定性等权衡；
- 哪些消融与主设计一致；
- 哪些结果改变了对方法价值的理解；
- 哪些异常结果适合成为分析而不是被忽略。

## 5. 建立文献位置

从 baseline 的 Related Work 和参考文献获得初始技术地图，但不以此为边界。围绕用户代码的真实变化同时检查：独立关键词检索、baseline 的前向引用、同一问题的其他技术路线、审稿人可能视为最近邻的方法，以及目标 venue 的近期同主题论文。

```text
任务路线
├── baseline 所属路线
├── 与核心变化最接近的路线
├── 可能被审稿人视为同类的方法
└── 本文与它们的实质差异
```

只把已经阅读并能确认内容的论文写入 Related Work。搜索结果摘要只用于发现候选文献。代码差异只能产生候选新颖性；完成足够的近邻文献核对后，才能把它写成相对现有工作的创新主张。

## 6. 生成和选择中心故事

先生成 2–3 个不同的论文身份。常见候选包括：

- **机制或信息流故事**：方法改变了表示、交互、优化或推理过程；
- **能力故事**：方法获得了过去不足的泛化、稳定性、效率或适应性；
- **经验发现故事**：实验揭示了对方法设计有普遍价值的模式；
- **统一框架故事**：多个已有元素被组织成一个有新功能的整体。

先做资格检查。以下四项全部成立，候选才可以竞争中心故事：

1. 代码或正式项目记录确认该方法思想已经实现；
2. 关键结果直接支持主张，或支持一个明确收窄后的版本；
3. 相反结果、混杂因素和适用条件已经计入；
4. 表述没有从观察越级到未经验证的因果机制或普遍结论。

未通过的候选可以保留为设计动机、解释性假设或未来工作，不能靠写作潜力补偿证据缺口。对合格候选再按四项排序：

| 维度 | 问题 |
|---|---|
| 差异性 | 与 baseline 和最近邻工作相比，实质变化是否清楚？ |
| 统一能力 | 它能否同时组织 Method、Experiments 和 Introduction？ |
| venue 适配 | 它是否符合目标社区常见的问题尺度与贡献类型？ |
| 表达潜力 | 它是否能被清楚、具体、不过度地讲述？ |

选择综合最强故事并继续。不要平均拼接几个彼此竞争的故事。

同时给主要主张标注写作边界：

| 主张状态 | 写法 |
|---|---|
| 代码确认的实现事实 | 直接陈述 |
| 实验直接观察 | 直接陈述并给出必要数字 |
| 与结果一致的解释 | 明确写成解释或可能原因 |
| 未经隔离实验验证的机制 | 只作为设计动机或假设 |

## 7. 输出项目档案

使用 [project-dossier-template.md](../assets/project-dossier-template.md)，至少包含：

- 一句话论文身份；
- baseline 与用户方法的核心差异；
- 本轮采用的材料版本与尚未解决的关键冲突；
- 主贡献与次贡献；
- 关键结果模式；
- 主张状态及主张—实验—图表映射；
- Related Work 的组织轴；
- 贯穿全文的术语表；
- 真正缺失且会影响正文的材料。

这份档案服务写作，不扩张成项目管理系统。
